# Computer Science

Use: problem -> representation -> mechanism or algorithm -> trace -> implementation fragment -> complexity -> edge cases -> exercise.

## Layout

Use state tables, memory diagrams, concise pseudocode, execution traces, and small code fragments. Highlight only the lines currently being explained.

## Required Checks

- Trace at least one concrete input.
- State invariants, preconditions, and failure cases.
- Verify code by running the smallest useful example when possible.
- Keep code readable from presentation distance.
- Distinguish conceptual pseudocode from executable syntax.
